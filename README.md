# AstrBot 群聊上下班插件

一个用于 AstrBot 的群聊状态控制插件。你可以在每个群里单独发送 `下班` 让机器人停止响应其他功能，再发送 `上班` 重新启用。

> 本版本已修复 **AstrBot 4.x 下「设置了管理员却提示不是管理员」** 的问题，并适配了新版 AstrBot 的插件接口。

## 功能

- 分群独立控制，不同群互不影响
- 下班后拦截当前群的后续消息，避免触发其他插件或 LLM
- 保留 `上班` 指令，方便随时恢复机器人响应
- 下班状态会持久化，插件重载或 AstrBot 重启后依然有效

## 指令

| 指令 | 作用 | 说明 |
| --- | --- | --- |
| `下班` | 关闭当前群聊的机器人功能 | 关闭后，该群里的大部分消息都会被拦截 |
| `上班` | 恢复当前群聊的机器人功能 | 恢复后，机器人重新响应该群消息 |

> 这两个指令仅允许 AstrBot 管理员使用（见下方「管理员配置」）。

## 安装

1. 将插件目录放入 AstrBot 的插件目录 `data/plugins/`，目录名建议为 `astrbot_plugin_work_status`。
2. 确认插件入口文件为 `main.py`。
3. 重启 AstrBot，或在 WebUI 的 `插件` 页点击 `重载插件`。

## 管理员配置（AstrBot 4.x）

AstrBot 4.x 起，管理员设置在 **配置文件** 里，而不是系统全局：

1. 在群里（或私聊机器人）发送 `/sid`，记下输出中的 `UID`。
2. 打开 WebUI，进入 `配置文件 → 访问控制 → 管理员 → 管理员 ID`，把 `UID` 加进去并保存。
3. **注意**：要修改机器人实际使用的那个配置文件。若机器人绑定了自定义配置文件，请在该配置文件中添加管理员。

插件现在直接使用 AstrBot 自己判定的管理员身份，不再自行读取默认配置里的管理员列表，因此与内置管理员指令（如 `/provider`、`/name`）的判定完全一致。

## 触发方式

AstrBot 的指令需要唤醒前缀（默认为 `/`）或 @ 机器人 才会触发：

- 群聊中发送 `/下班`、`/上班`
- 或 `@机器人 下班`

如果你修改过唤醒前缀，请使用新的前缀（例如 `!下班`）。

## 数据存储

下班状态保存在 AstrBot 数据目录：

```text
data/plugin_data/astrbot_plugin_work_status/work_status.json
```

插件更新、重装不会覆盖该文件；如需清空下班状态，停止 AstrBot 后删除该文件即可。

## 原理

插件注册了一个优先级很高的群聊消息监听器：

- `下班` 时，把当前群加入“停用”列表，并把状态写入数据文件
- 处于“下班”状态时，除 `上班` / `下班` 指令本身外的消息都会调用 `event.stop_event()` 拦截，阻止后续插件链和模型回复
- `上班` 时，把当前群从“停用”列表移除

判断管理员时优先读取 AstrBot 在消息处理阶段写入的 `event.role`（与内置管理员指令一致），仅在无法获取时才回退到配置文件中的 `admins_id`。

## 兼容性

- 适配 AstrBot 4.x（`>=4.0.0`），已在 4.29 的接口上核对。
- 仍兼容旧版事件对象：群号获取、管理员比对均有回退逻辑。

## 常见问题

**Q：发送 `/下班` 仍然提示“只有管理员可以使用”？**

A：请用 `/sid` 确认输出中的 `UID`，并确认它被加到了 **机器人当前使用的配置文件** 的「访问控制 → 管理员」里（不是别的配置文件）。保存后不需要重载插件，插件每次都会读取 AstrBot 判定的最新身份。

**Q：下班后发送 `/上班` 没有反应？**

A：确认发送时带有唤醒前缀（默认 `/`）或 @ 了机器人；下班状态下只放行 `上班` / `下班` 指令本身，其他消息都会被静默拦截。
